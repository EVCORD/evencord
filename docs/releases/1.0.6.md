# EvenCord 1.0.6

EvenClean's search and cleanup workflow now distinguishes actual Discord requests from pacing, rate-limit and indexing waits. The window shows the current conversation, page count, response elapsed time and a cooldown countdown. Find my messages is visible at the top, errors appear above the selectors, and a completed preview scrolls the review area into view. Deletion instructions explicitly explain the checkbox, exact confirmation phrase and Delete button.

New previews default to 100 messages. Searches are bounded to 20 pages across the entire batch instead of up to 200 pages per conversation. Review results now finishes the current page and makes the collected partial batch available for confirmation. A complete final page no longer causes an unnecessary additional search; pagination uses an exclusive cursor and accepts validated search results without explicit hit markers.

A request that remains unanswered for 30 seconds stops the batch with a specific error. Stop also releases the busy interface while a request is pending. Because Discord's REST wrapper cannot reliably cancel an already-issued request, EvenClean blocks further jobs until that request settles. Late responses cannot add messages to the abandoned preview or falsely report a deletion as successful. Late rate-limit responses still preserve the cooldown. An in-flight deletion may complete after a timeout or Stop; review the channel before retrying.

Focused synthetic checks cover search/deletion timeouts, pending-request exclusion, cancellation, late rate limits, indexing waits, pagination, partial review, ownership and confirmation. TypeScript, lint, build and signed-package verification are checked separately. No real Discord messages were searched or deleted, and no browser or live Discord UI test was performed. These changes address verified failure paths; they are not a claim that every live Discord search condition has been reproduced.
